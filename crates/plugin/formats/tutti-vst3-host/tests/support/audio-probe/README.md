# audio-probe

A reference VST3 plugin whose output is a **closed-form function of its input**,
used to test that this host hands plugins the right samples in the right slots
at the right times.

It is ours, not Steinberg's — it is not an SDK sample.

## Why it exists

Every other test in this crate is structural: HostChecker proves the
`ProcessData` was *shaped* legally (bus counts agree, no null pointers, events
sorted), but never looks at a sample value. A host that hands the plugin a
perfectly-formed struct full of the *wrong audio* — swapped channels, an aux bus
wired onto the main one, automation applied at the wrong offset — passes all 185
of those checks silently.

`audio-probe` closes that gap. Each mode makes some host behaviour observable in
the output samples, so the test can compute what a correct host would produce
and compare exactly. See `source/probeids.h` for the mode list and the wire
contract; `tests/vst3_audio_correctness.rs` mirrors those constants.

The probe declares a deliberately **asymmetric** layout — input buses `[2, 1]`,
output buses `[2, 1]` — because a host that assumes "one stereo bus in, one
stereo bus out" (the shape of every other sample plugin) would otherwise be
accidentally correct.

## How it is built

`build.rs` compiles these sources plus the ~40 SDK translation units they need
and links a real `.vst3` bundle into `OUT_DIR`, as part of the same `cargo test`
invocation. No CMake. The only requirement is `VST3_SDK_DIR` pointing at a full
SDK checkout, and the `conformance` feature:

```bash
VST3_SDK_DIR=/path/to/vst3sdk \
cargo test -p tutti-vst3-host --features conformance
```

`cc` can only emit static libraries, and a static library is the wrong shape for
a plugin — the linker drops archive members nothing references, and a plugin's
entry points are referenced only by the host at `dlopen` time. So build.rs
compiles to objects and runs the `-shared` link itself.

`projectversion.h` is generated by the SDK's CMake from a template, so build.rs
writes a minimal one into `OUT_DIR`.

## Why absence is a hard failure

The tests **panic** rather than skip when the probe cannot be found. The probe is
built from this tree, so its absence is a build failure, not a property of the
machine.

This is not hypothetical. The bundle previously lived at a machine-specific path
outside the repo, and the test resolved it by a hardcoded filename. Building it
under a different name made all nine tests skip *while printing
`test result: ok. 9 passed`* — the suite reported success having executed
nothing. Any change here must keep a missing probe loud.

## Adding a mode

1. Add the enum value and any constants to `source/probeids.h`.
2. Implement it in `ProbeProcessor::process` (`source/probeprocessor.cpp`).
3. Mirror the constants in `tests/vst3_audio_correctness.rs` — they are a wire
   contract between the two files and there is no compiler check on them.
4. Verify the new assertion is non-vacuous by mutating the probe (e.g. shift a
   tag by one) and confirming the test fails.

Step 4 is not optional: a test that cannot fail is worse than no test, because
it reports coverage that does not exist.
